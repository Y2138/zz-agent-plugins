# Specz 变更日志

## 2.3.0

- `specz-brief` 使用功能与设计单主线生成中文评审文档，按界面、服务、数据或集成的实际变化选用细节，避免重复叙述。
- 界面方案按需覆盖交互状态与可见反馈；接口、数据库和上线内容仅在实际涉及时保留，图示按评审重点选择。

## 2.2.0

- 新增可选 `specz-brief`，将已形成的设计方案沉淀为结构稳定的中文《评审说明》。
- 提供评审模板，固定目标与范围、代码事实、方案总览、关键决策、交付模块、验收映射、风险和待确认事项。
- 业务流程与技术实现主链路分开表达，简单局部修改不强制生成图示。
- 接口方法、真实路径和 SQL 必须来自代码或契约事实，无法确认时明确标记。
- 上线、迁移、配置、脚本、灰度、监控和回滚内容按需加载独立模块。
- 明确信息性质与证据要求，避免把方案建议写成代码事实、把计划验证写成已通过结果。
- 评审文档不要求创建 bundle，不修改状态账本，也不自动实施方案。

## 2.0.0

- 将原有完整规范工作流迁移为 `specx`，保留六阶段技能、bundle artifacts、独立验证和归档能力。
- 重新设计 `specz`，面向高能力编码模型，默认直接执行普通任务。
- 取消 Size Routing、强制阶段切换、默认子智能体、固定修复轮数和强制归档。
- 仅在恢复、协作、审批或审计确有收益时创建单文件中文状态账本。
- 大任务按依赖就绪的任务或紧耦合模块分波执行，完成局部验证后推进，最后执行一次集成验证。
