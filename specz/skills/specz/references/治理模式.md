# 治理模式

仅在存在不可逆操作、数据/权限/部署风险、明确审批点或审计要求时读取。治理模式仍使用同一个 `状态.md`，不要再创建一套平行文档。

## 需要额外记录的内容

在状态账本中按需增加：

```markdown
## 审批与风险

- 风险事件：<可能造成的实际影响>
- 缓解措施：<回滚、备份、灰度、权限隔离或其他措施>
- 所需批准：<批准人或批准条件>
- 批准状态：待确认 | 已批准 | 已拒绝
- 批准证据：<用户确认、工单、变更记录或其他可复查来源>
```

## 不可妥协的边界

- 未获得必要授权前，不执行破坏性、生产写入、权限提升或不可逆操作。
- 不把执行者的完成声明当作验证证据。
- 关键行为使用新鲜证据；静态检查不能证明运行时行为时，选择能够观察真实结果的验证方式。
- 多执行者不得同时写入同一文件、共享状态或未隔离的外部资源。
- 发现目标、验收或风险假设失效时，暂停受影响任务并请求决策，不为了维持原计划继续执行。

## 验证分层

- 执行者负责当前任务的针对性验证。
- 主上下文负责检查改动边界、风险控制和证据可信度。
- 所有任务完成后执行一次集成验证。
- 只有高风险结论、可疑证据或失败修复需要独立复验；不要无条件重跑可靠的确定性检查。
