# 通用项目记忆协议

本文档定义 Specz 如何使用项目级记忆。项目记忆是 agent / 项目层能力，职责类似 `AGENTS.md` 这类项目指令文件；它不是 Specz bundle，不属于 `specs/*/` 状态机，也不替代当前代码和当前规格。

## 来源

按当前平台和项目实际可用能力读取，常见来源包括：

- 平台提供的长期记忆或项目记忆
- 当前项目会被 agent 自动加载的指令文件，例如 `AGENTS.md`、`SYSTEM.md`、`CLAUDE.md`
- 项目明确声明为 memory / knowledge / conventions / decisions 的文档
- 用户在当前对话中明确提供的长期项目背景

不要为了 Specz 强制创建新的私有记忆目录。若项目已经有通用记忆机制，优先使用现有机制。

## 权威顺序

当记忆与当前上下文冲突时，按以下顺序处理：

1. system / developer / 平台安全约束
2. 用户当前请求和明确指令
3. 当前项目指令文件
4. active Specz bundle：`spec.md`、`design.md`、`tasks.md`、`verification.md`
5. 当前代码、运行结果、测试、日志和实际证据
6. 通用项目记忆
7. `specs/archive/` 历史记录

记忆只能作为上下文和经验提示；不能作为当前事实或验证证据。

## 阶段使用方式

- `specz-flow`：读取相关记忆帮助选择或创建 bundle，但不因记忆缺失而阻塞路由。
- `specz-clarify`：用记忆理解术语、边界、历史偏好，减少不必要的澄清问题。
- `specz-plan`：用记忆识别约定、历史决策和风险，但技术事实必须用当前代码或明确证据验证。
- `specz-brief`：用记忆保持表达、术语和读者上下文一致，不从记忆引入新需求。
- `specz-run`：用记忆指导项目约定、已知坑、验证习惯和清理要求；不得把记忆当作 PASS 证据。
- `specz-archive`：可记录对通用记忆有价值的候选经验，但不默认写入通用记忆。

## 写入规则

Specz 默认只消费通用项目记忆，不直接维护它。

只有在以下情况才可以写入或更新通用项目记忆：

- 用户明确要求更新记忆
- 当前平台有明确的通用记忆写入工作流，并且该工作流允许当前任务写入
- 项目指令文件明确规定某类经验必须沉淀到指定记忆位置

否则，阶段结果中可以列出 `Memory candidates`，由用户或通用记忆系统决定是否采纳。

## 失效处理

当记忆可能过期、与代码冲突或缺少证据时：

- 不要静默采用
- 在计划或结果中标明它是待验证背景
- 使用当前代码、命令、测试或运行时证据重新确认
- 如果无法确认，记录为 `ASSUMPTION-*` 或 `BLOCKER-*`
