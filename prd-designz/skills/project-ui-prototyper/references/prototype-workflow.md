# 原型生成工作流

项目 UI 规则就位后使用此流程。

## 1. 需求提取

从 PRD、页面需求、流程、截图或草图中提取：

- 页面或流程名称
- 用户主目标
- 必需区块和数据
- 主要和次要操作
- 空态、加载态、错误态、禁用态、成功态
- 权限或角色差异
- 响应式目标（如适用）

若某必需状态缺失，使用项目已有状态模式并标注内容假设。

## 2. 模式映射

将需求页面映射到最接近的已有项目模式：

| 需求类型 | 优先已有模式 |
|---|---|
| 列表/管理页 | 表格、筛选栏、批量操作、抽屉/模态详情 |
| 详情页 | header 摘要、Tab、元数据、动态/feed 面板 |
| 创建/编辑流程 | 表单布局、校验、提交/取消模式 |
| 仪表盘 | 指标卡片、图表区、表格/列表下钻 |
| 设置页 | 分组表单区块、危险操作位置 |
| 审核/审批 | 对比布局、状态徽章、评论、操作 footer |

在输出摘要中记录所选模式。

若 project-specific skill 为所选模式提供了可复用的 `assets/` 脚手架，生成 HTML 前先读取对应资产。优先适配脚手架的槽位/props，而非从文字描述重建固定项目外框。

## 3. 技术栈选择

原型优先使用项目原始 UI 技术栈：

1. 当检测到的项目框架和组件库能安全用于独立 HTML 文件时，直接使用
2. 若确切组件库无法在无构建步骤下加载，用 inline CSS/JS 复现其视觉和交互模式
3. 仅在保留项目 Token、密度、组件形状和状态的前提下才降级为原生 HTML/CSS/JS

示例：
- React 项目：使用固定版本 CDN 的 React/Babel 或项目文档中的原型方案
- Vue 项目：可行时使用固定版本 CDN 的 Vue 浏览器构建
- 组件库项目：有稳定 CDN/浏览器兼容资产时直接用；否则用项目 Token 模拟组件样式

原型可交付物不得要求构建步骤、dev server、npm install 或 bundler。

## 4. DESIGN.md 输出

项目一致原型的 DESIGN.md 应精简且面向页面：

```markdown
# 设计规格：[页面名称]

## 项目 UI 基础
- 来源 skill / references：
- 最接近的已有模式：
- 使用的 Token：

## 页面目标
## 信息架构
## 组件方案
## 布局规则
## 交互与状态
## 原型备注
## 假设
```

## 5. HTML 原型输出

生成**一个**独立 HTML 文件。

要求：
- 所有原型专属 CSS 和 JS inline 在文件中
- 不需要构建步骤、本地 dev server、源码导入或多文件依赖
- 使用项目 Token 和组件模式
- 复用提供的项目 UI 脚手架（`assets/`）作为固定外壳：侧栏/顶栏 admin 框架、表格页外壳、详情页外壳、仪表盘、模态框、抽屉
- 优先原始框架/组件库（能安全用于独立文件时）；否则用原生 HTML/CSS/JS 忠实模拟
- 使用原始字体、Logo、图标和图片（可内嵌或稳定 URL 引用时）
- 不在可交付物中保留原始本地项目路径——关键本地资产用 data URI 内嵌、可访问 URL 或诚实占位符替换
- 固定格式 UI 用显式尺寸、grid track 或响应式约束保持稳定
- 按需包含真实状态：加载、空、错误、选中、禁用
- 有真实或提供的资产时使用；否则用诚实占位符
- 确保文字在移动端和桌面端不越界

使用资产脚手架时，将其组件或标记内联到独立 HTML 中，仅填充页面特定槽位。不在可交付物中保留外部本地文件导入。

React/Babel 或 Vue 原型使用项目或父 skill 中记录的固定版本 CDN。

## 6. 浏览器预览验证

生成 HTML 后在浏览器中打开再交付。

验证：
- 页面正常渲染，不白屏
- 浏览器控制台无 JS 错误
- 核心布局区域、控件和状态可见
- 文字无明显截断、重叠或溢出
- CDN 或资产加载失败时有安全降级

预览失败则修复 HTML 并重新预览。

## 7. 扩展说明

当引入项目 references 中不存在的模式时，解释：

- 为什么已有模式不适用
- 复用了哪些项目 Token/组件
- 哪些需要产品/设计确认

扩展保持最小化。
